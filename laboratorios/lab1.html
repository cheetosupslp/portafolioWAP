01

Objetivo de la Práctica

Demostrar la identificación y explotación de una vulnerabilidad de File Path Traversal en su variante más simple, utilizando Burp Suite como herramienta principal. El objetivo es recuperar el contenido del archivo /etc/passwd del servidor mediante la manipulación del parámetro filename en las peticiones de imágenes de la aplicación vulnerable de PortSwigger Web Security Academy.

02

Marco Teórico

File Path Traversal (también conocido como Directory Traversal) es una vulnerabilidad de seguridad web que permite a un atacante acceder a archivos y directorios fuera del directorio raíz previsto de la aplicación. Esto se logra mediante la manipulación de parámetros que el servidor utiliza para construir rutas de archivos, generalmente usando secuencias como ../ para subir niveles en el sistema de archivos.

Esta vulnerabilidad compromete principalmente el principio de Confidencialidad del modelo CIA (Confidencialidad, Integridad y Disponibilidad), ya que permite la lectura no autorizada de archivos sensibles del servidor.

Según el OWASP Top 10 2021, Path Traversal se encuentra dentro de la categoría A01:2021 – Broken Access Control, una de las más críticas y frecuentes.

Variantes principales:

  • Simple Path Traversal: No existe ningún tipo de filtrado (caso de este laboratorio).
  • Traversal con filtros: La aplicación intenta bloquear las secuencias ../.
  • Absolute Path Bypass: Se utiliza una ruta absoluta en lugar de relativa.
  • Null Byte Injection: Se usa el carácter nulo (%00) para evadir validaciones.
03

Desarrollo

1. Acceso al laboratorio

Se accedió al laboratorio oficial de PortSwigger: 

https://portswigger.net/web-security/file-path-traversal/lab-simple

Al hacer clic en Access the lab se carga una aplicación de tienda en línea vulnerable.

2. Configuración de Burp Suite

Se utilizó Burp Suite Community Edition. Se abrió el navegador integrado desde la pestaña Proxy → Intercept → Open Browser para que todo el tráfico pasara a través del proxy.

3. Identificación del parámetro vulnerable

Al navegar por los productos de la tienda se observó que las imágenes se cargan mediante peticiones del tipo: 

GET /image?filename=XX.jpg HTTP/1.1

El parámetro filename es controlado por el usuario y se utiliza directamente para construir la ruta del archivo en el servidor, convirtiéndolo en un vector de ataque de Path Traversal.

4. Explotación

Se siguió el siguiente procedimiento:

  1. Se interceptó la petición de una imagen con Intercept is on.
  2. Se envió la petición a Repeater (clic derecho → Send to Repeater).
  3. Se modificó el valor del parámetro filename por el siguiente payload:
../../../etc/passwd

La petición final quedó de la siguiente forma:

GET /image?filename=../../../etc/passwd HTTP/1.1

Al enviar la petición modificada, el servidor devolvió el contenido completo del archivo /etc/passwd, resolviendo el laboratorio.

04

Explicación Técnica del Payload

El payload utilizado fue: 

../../../etc/passwd

¿Por qué funciona?

Las imágenes de la aplicación se almacenan normalmente en una ruta similar a: 

/var/www/images/

Cuando el servidor recibe el parámetro filename=../../../etc/passwd, concatena este valor a la ruta base, resultando en: 

/var/www/images/../../../etc/passwd

Cada secuencia ../ indica al sistema operativo que suba un nivel en la estructura de directorios:

  • Primer ../ → sale de /images/
  • Segundo ../ → sale de /www/
  • Tercer ../ → sale de /var/ y llega a la raíz del sistema (/)

Finalmente, el servidor intenta leer el archivo /etc/passwd, el cual contiene información de las cuentas de usuario del sistema Linux.

En este laboratorio (Simple Case) no existe ningún tipo de filtrado ni validación de la entrada, por lo que el ataque funciona de forma directa. Este es el escenario más básico de Path Traversal.

05

Conclusiones

En este laboratorio se demostró de forma práctica la existencia y explotación de una vulnerabilidad de File Path Traversal en su variante más simple. Mediante la manipulación del parámetro filename y el uso de secuencias de recorrido de directorios (../), fue posible acceder al archivo sensible /etc/passwd del servidor.

Esta práctica refuerza la importancia de validar y sanitizar correctamente todas las entradas de usuario que intervienen en la construcción de rutas de archivos, así como de aplicar los principios de mínimo privilegio y control de acceso adecuados para proteger la confidencialidad de la información del sistema.

El uso de Burp Suite (Proxy + Repeater) resultó fundamental para interceptar, modificar y analizar las peticiones de forma controlada y profesional.
