01

Objetivo de la Práctica

Demostrar la identificación y explotación de una vulnerabilidad de File Path Traversal en la que la aplicación elimina las secuencias de recorrido (../) de forma no recursiva. El objetivo es recuperar el contenido del archivo /etc/passwd mediante el uso de secuencias anidadas que logran evadir el filtro.

02

Marco Teórico

File Path Traversal es una vulnerabilidad que permite a un atacante acceder a archivos fuera del directorio permitido mediante la manipulación de parámetros que construyen rutas de archivos.

Esta vulnerabilidad afecta principalmente el principio de Confidencialidad del modelo CIA y se encuentra catalogada dentro de A01:2021 – Broken Access Control del OWASP Top 10.

En este laboratorio la aplicación elimina las secuencias ../ del nombre del archivo, pero lo hace de forma no recursiva (solo una pasada). Esta debilidad permite el uso de secuencias anidadas como ....// para evadir el filtro.

03

Desarrollo

1. Acceso al laboratorio

Se accedió al laboratorio oficial de PortSwigger: 

https://portswigger.net/web-security/file-path-traversal/lab-sequences-stripped-non-recursively

Al hacer clic en Access the lab se carga una aplicación de tienda en línea vulnerable.

2. Configuración de Burp Suite

Se utilizó Burp Suite Community Edition. Se abrió el navegador integrado desde la pestaña Proxy → Intercept → Open Browser para que todo el tráfico pasara a través del proxy.

3. Identificación del parámetro vulnerable

Al navegar por los productos se observó que las imágenes se cargan mediante peticiones del tipo: 

GET /image?filename=XX.jpg HTTP/1.1

El parámetro filename es controlado por el usuario y se utiliza para construir la ruta del archivo en el servidor.

4. Prueba de payloads anteriores

Se probaron los payloads de los laboratorios anteriores: 

../../../etc/passwd
/etc/passwd

Ambos fallaron, confirmando que la aplicación elimina las secuencias ../.

5. Explotación con secuencias anidadas

Se modificó el parámetro filename por el siguiente payload: 

....//....//....//etc/passwd

La petición final quedó de la siguiente forma:

GET /image?filename=....//....//....//etc/passwd HTTP/1.1

Al enviar la petición, el servidor devolvió el contenido completo del archivo /etc/passwd, resolviendo el laboratorio.

04

Explicación Técnica del Payload

El payload utilizado fue: 

....//....//....//etc/passwd

¿Por qué funciona?

La aplicación elimina las secuencias ../ del nombre del archivo, pero lo hace de forma no recursiva (solo realiza una pasada de limpieza).

Cuando enviamos ....//, el servidor elimina la secuencia interna ../, convirtiendo cada ....// en ../.

Después de la limpieza, el valor se transforma en: 

../../../etc/passwd

De esta forma se logra un payload de Path Traversal válido que el filtro no logra eliminar completamente.

05

Conclusiones

En este laboratorio se demostró que eliminar las secuencias ../ de forma no recursiva no es una defensa suficiente. Mediante el uso de secuencias anidadas (....// fue posible evadir el filtro y acceder al archivo /etc/passwd.

Esta práctica refuerza la importancia de implementar filtros recursivos o, preferiblemente, validaciones basadas en listas blancas y canonicalización de rutas para prevenir vulnerabilidades de Path Traversal de manera efectiva.

El uso de Burp Suite (Proxy + Repeater) facilitó la identificación y prueba de diferentes variantes del payload de forma controlada.
