01

Objetivo de la Práctica

Demostrar la identificación y explotación de una vulnerabilidad de File Path Traversal en la que la aplicación valida que el nombre del archivo termine con una extensión permitida. El objetivo es recuperar el contenido del archivo /etc/passwd mediante el uso del null byte (%00) para evadir dicha validación.

02

Marco Teórico

File Path Traversal es una vulnerabilidad que permite a un atacante acceder a archivos fuera del directorio permitido mediante la manipulación de parámetros que construyen rutas de archivos.

Esta vulnerabilidad afecta principalmente el principio de Confidencialidad del modelo CIA y se encuentra catalogada dentro de A01:2021 – Broken Access Control del OWASP Top 10.

En este laboratorio la aplicación valida que el nombre del archivo termine con una extensión esperada (por ejemplo .png o .jpg). Esta protección puede ser evadida utilizando el null byte (%00), que en muchos sistemas indica el final de una cadena de texto.

03

Desarrollo

1. Acceso al laboratorio

Se accedió al laboratorio oficial de PortSwigger: 

https://portswigger.net/web-security/file-path-traversal/lab-validate-file-extension-null-byte-bypass

Al hacer clic en Access the lab se carga una aplicación de tienda en línea vulnerable.

2. Configuración de Burp Suite

Se utilizó Burp Suite Community Edition. Se abrió el navegador integrado desde la pestaña Proxy → Intercept → Open Browser para que todo el tráfico pasara a través del proxy.

3. Identificación del parámetro vulnerable

Al navegar por los productos se observó que las imágenes se cargan mediante peticiones del tipo: 

GET /image?filename=XX.jpg HTTP/1.1

El parámetro filename es controlado por el usuario. La aplicación valida que el valor termine con una extensión permitida.

4. Prueba de payloads anteriores

Se probaron los payloads de los laboratorios anteriores: 

../../../etc/passwd
/etc/passwd
....//....//....//etc/passwd
..%252f..%252f..%252fetc/passwd
/var/www/images/../../../etc/passwd

Todos fallaron porque no cumplían con la validación de extensión de archivo.

5. Explotación con Null Byte Bypass

Se modificó el parámetro filename por el siguiente payload: 

../../../etc/passwd%00.png

La petición final quedó de la siguiente forma:

GET /image?filename=../../../etc/passwd%00.png HTTP/1.1

Al enviar la petición, el servidor devolvió el contenido completo del archivo /etc/passwd, resolviendo el laboratorio.

04

Explicación Técnica del Payload

El payload utilizado fue: 

../../../etc/passwd%00.png

¿Por qué funciona?

La aplicación valida que el nombre del archivo termine con una extensión permitida (por ejemplo .png o .jpg).

El carácter nulo (%00 o null byte) tiene un significado especial en muchos lenguajes de programación (especialmente en C y sistemas más antiguos): indica el final de una cadena.

Cuando se envía ../../../etc/passwd%00.png:

  1. La validación de extensión se cumple porque el valor termina en .png.
  2. Al procesar la cadena, el null byte (%00) hace que el sistema considere que el nombre del archivo termina justo antes del %00.
  3. Por lo tanto, la ruta real que se utiliza es ../../../etc/passwd.
  4. Se logra el Path Traversal y se lee el archivo /etc/passwd.
05

Conclusiones

En este laboratorio se demostró que validar únicamente la extensión de un archivo no es una defensa suficiente. Mediante el uso del null byte (%00) fue posible evadir la validación y acceder al archivo /etc/passwd.

Esta práctica refuerza la importancia de implementar validaciones robustas que no dependan únicamente de la extensión del archivo, así como de utilizar funciones modernas que manejen correctamente las cadenas de texto y eviten el truncamiento por null bytes.

El uso de Burp Suite (Proxy + Repeater) facilitó la prueba controlada del payload con null byte de forma precisa.
