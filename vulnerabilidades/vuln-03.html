VULN-03

"Exposición masiva de datos personales mediante IDOR (Broken Object Level Authorization)"

← Volver al proyecto PR02

Descripción técnica y causa raíz

El portal y las APIs de servicios ciudadanos permiten a un usuario autenticado consultar los expedientes, historial de consumo y datos personales (PII) de cualquier otro ciudadano simplemente alterando los parámetros de identificación en la URL o en el cuerpo de la petición.

Causa raíz: Ausencia de controles de autorización a nivel de objeto (BOLA/IDOR). El servidor procesa la solicitud basándose únicamente en el ID proporcionado por el cliente, sin validar en el backend si el recurso solicitado pertenece legítimamente al usuario dueño de la sesión actual.

Comprobación de los hallazgos

  1. Se inició sesión en el portal institucional con una cuenta de usuario estándar.
  2. Se interceptó la petición HTTP encargada de consultar el perfil o recibo de consumo.
  3. Se modificó el parámetro identificador (ej. id o account) por el de un tercero.
  4. El servidor devolvió la respuesta con la Información de Identificación Personal (PII) completa y el historial de consumo del otro usuario.

Impacto y riesgo

Nivel Crítico. Esta vulnerabilidad permite el "raspado" (scraping) o exfiltración masiva de la base de datos de ciudadanos. La exposición de nombres, domicilios e historiales financieros constituye una violación directa a la Ley de Protección de Datos Personales (LFPDPPP), conllevando severas sanciones regulatorias y una crisis reputacional inmediata para la institución.

Mitigaciones

  • Implementar una validación estricta de autorización a nivel de objeto (BOLA) en cada endpoint de la API.
  • Asegurar que las consultas a la base de datos extraigan el identificador del usuario directamente de la sesión activa del servidor ($_SESSION), ignorando el ID enviado por el cliente.
  • Sustituir el uso de identificadores secuenciales predecibles por Identificadores Únicos Universales (UUID) o hashes indirectos.
