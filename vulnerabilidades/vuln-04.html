VULN-04

"Exposición de código fuente mediante archivos de respaldo (.bak)"

← Volver al proyecto PR02

Descripción técnica y causa raíz

Durante la auditoría se descubrió que el servidor web entregaba en texto plano el código fuente del backend de la aplicación al solicitar archivos con extensiones de copia de seguridad (como .bak o .old). Estos archivos fueron generados por editores de texto directamente en el entorno de producción.

Causa raíz: Prácticas deficientes en la gestión del cambio y control de acceso al código fuente. El servidor web está configurado para procesar e interpretar únicamente archivos .php, por lo que cualquier otra extensión desconocida (como .bak) es servida directamente al cliente sin ejecutarse, revelando su contenido íntegro.

Comprobación de los hallazgos

  1. Se realizó un escaneo pasivo y enumeración de directorios en el portal institucional.
  2. Se identificaron archivos de lógica de negocio terminados en extensiones de respaldo (ej. archivo.php.bak).
  3. Se emitió una petición HTTP GET directa hacia el archivo identificado.
  4. El servidor web respondió con el código fuente del backend en texto claro, revelando consultas a base de datos y la estructura interna.

Impacto y riesgo

Nivel Alto. La exposición del código fuente representa un riesgo crítico de reconocimiento avanzado (White-Box Testing). Permite a un actor malicioso analizar la lógica de negocio sin interactuar a ciegas, facilitando el descubrimiento de vulnerabilidades complejas como Inyecciones SQL (VULN-07) o fallas lógicas en las pasarelas de pago, además de exponer posibles credenciales hardcodeadas.

Mitigaciones

  • Prohibir estrictamente la modificación de código directamente en los servidores de producción.
  • Configurar el servidor web (ej. Apache FilesMatch) para denegar categóricamente el acceso HTTP a extensiones como .bak, .old, .inc y .log.
  • Implementar procesos automatizados de CI/CD que garanticen despliegues limpios sin artefactos ni archivos temporales del entorno de desarrollo.
