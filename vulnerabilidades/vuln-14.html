VULN-14

"Falla Lógica en la Validación de Vínculos Contractuales (Inconsistencia Relacional)"

← Volver al proyecto PR02

Descripción técnica y causa raíz

El sistema certifica incorrectamente la existencia de un vínculo entre un contrato y un proveedor. Al suministrar el ID de un contrato real y modificar el ID del proveedor por el de una empresa no relacionada, la aplicación devuelve una respuesta de validación exitosa en lugar de rechazar la petición.

Causa raíz: El backend procesa la solicitud evaluando la existencia de las entidades de forma aislada (verifica que el contract_id exista en la base de datos y que el provider_id corresponda a un proveedor vigente), pero omite realizar la consulta relacional (JOIN) que certifique que ese contrato específico fue adjudicado a ese proveedor específico. Existe una falla severa en la validación de la lógica de negocio y en la integridad de las consultas.

Comprobación de los hallazgos

  1. Se ingresó al padrón de proveedores en http://localhost:8080/proveedores.php y se navegó a la sección "Contrataciones".
  2. Se ejecutó la función "Validar vínculo" sobre una contratación existente, interceptando la petición HTTP GET.
  3. Se registró la URL original: http://localhost:8080/validar-vinculo-contractual.php?contract_id=51&provider_id=171.
  4. Se consultó el padrón público para obtener el ID de un proveedor diferente (ej. ID 154 correspondiente a "Ambiental del Bajio Ingenieria").
  5. Se modificó la petición alterando únicamente el proveedor: contract_id=51&provider_id=154.
  6. El sistema falló en detectar la inconsistencia, validando positivamente la relación falsa y revelando la bandera.

Impacto y riesgo

Integridad y No Repudio (Nivel Crítico): La aplicación emite comprobantes oficiales o pantallas de validación para relaciones contractuales ficticias. Un tercero puede usar esta plataforma para demostrar falsamente a bancos o autoridades que tiene un contrato adjudicado con INTERAFAS.

Riesgo Legal y Reputacional: Habilita escenarios de fraude corporativo, corrupción y suplantación. Si un ente auditor descubre que el sistema valida contratos falsos, la reputación de la infraestructura crítica quedará totalmente destruida.

Cadena de ataque

Esta vulnerabilidad funciona como un vector facilitador para ataques de ingeniería social e infiltración en la cadena de suministro. Un atacante que ha logrado obtener el ID de un contrato interno mediante un IDOR previo (VULN-03) puede usar esta falla lógica para generar pruebas falsas de adjudicación, presentándolas a los empleados de INTERAFAS para exigir pagos, accesos o información confidencial.

Mitigaciones

  • Corrección de Consultas Relacionales: Modificar el código fuente en validar-vinculo-contractual.php para que la consulta SQL utilice cláusulas de relación estricta (JOIN o WHERE) que exijan la coincidencia de ambas claves foráneas. Ejemplo: SELECT * FROM contratos WHERE id = ? AND id_proveedor = ?.
  • Pruebas de Casos Negativos (Unit Testing): Integrar pruebas automatizadas que envíen combinaciones de identificadores no correspondientes, asegurando que el backend responda con "Vínculo no localizado" o un error HTTP 400.
